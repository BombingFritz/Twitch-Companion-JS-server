# Fehlerhistorie

| Symptom | Ursache | Fix | Regel zur Vermeidung |
|---|---|---|---|
| Shoutouts kamen unzuverlässig oder gar nicht | Chat-Befehl `/shoutout` statt API | `POST /helix/chat/shoutouts`, Scope `moderator:manage:shoutouts` | Shoutouts nur über die Helix-API senden |
| `Cannot find module 'ws'` beim Start | `node_modules` fehlt im kopierten Ordner (z. B. Backup) | `npm install` im jeweiligen Ordner | `node_modules` wird nicht mitkopiert; nach jedem Kopieren Abhängigkeiten installieren |
| `invalid subscription type and version` | Falscher Typ `channel.stream.online` | Umbenannt auf `stream.online` (benötigt keine Autorisierung) | Typ-Namen gegen die Twitch-EventSub-Referenz prüfen |
| Konsolenbefehle wie `whitelist list` als „unbekannter Befehl“ abgelehnt | Doppelt escapte Regex `/\\s+/` statt `/\s+/` und doppelt escapte `\n` in Logs | Regex korrigiert, Escapes durch `console.log('')` ersetzt | Vor jeder Auslieferung `node --check server.js` |
| Log-Spam durch Polling | Widgets pollen, jede Anfrage wurde geloggt | `logIfChanged()` und entrauschter HTTP-Logger | Wiederholte Meldungen über `logIfChanged()` |
| Sub- und Gift-Effekte feuern Sekunden vor der Chat-Ankündigung und teils doppelt | Effekte hingen an `channel.subscribe`, `channel.subscription.message` und `channel.subscription.gift`; laut Code-Kommentar treffen diese oft vor der Chat-Ankündigung ein. Twitch-seitige Ursache: [UNGEKLÄRT] | Effekte nur aus `channel.chat.notification`, Gift-Bomb als ein Effekt, Entdoppelung über `message_id` und Zeitfenster | Neue Effekt-Auslöser an der Chat-Ankündigung ausrichten; nie mehrere Event-Typen für dasselbe Ereignis in `scheduleEffect` einspeisen |
| Nach einem von Twitch angeforderten `session_reconnect` drohten verlorene Events oder doppelte Verbindungen | Die neue Verbindung zur `reconnect_url` bekam keine Event-Handler; gleichzeitig löste das Schließen der alten Verbindung über `close` einen zweiten, frischen Verbindungsaufbau aus | `connectEventSub(reconnectUrl)` hängt Handler an jede Verbindung, schließt die alte erst nach `session_welcome` der neuen; nur das Ende der aktiven Verbindung (`eventSubWs`) löst einen Neuaufbau aus | Neue WebSockets immer über `connectEventSub()` erzeugen, nie direkt `new WebSocket()` |
| Widgets in OBS erhalten nach einem OBS-Update keinen Token mehr, im normalen Browser funktionieren sie | Die neuere Chromium-Version in OBS sperrt Anfragen von „Lokale Datei“-Seiten (`http://absolute`) an `localhost` („Local Network Access“); die Anfrage erreicht den Server nicht. Bestätigt am 01.11.2026 mit dem Polling-Widget | Browser-Source ohne „Lokale Datei“, stattdessen URL `file:///…` (Herkunft `null`) | Fehlt im Log die `/token`-Anfrage eines Widgets, liegt es am Browser, nicht am Server. Widgets nicht als „Lokale Datei“ einbinden; Option „Widgets vom Server ausliefern“ siehe OFFEN.md (K1) |
| Raider auf der Whitelist bekam nach dem Raid-Shoutout bei seiner ersten Chat-Nachricht einen zweiten Versuch, Twitch lehnte mit 429 ab (Livestream 03.11.2026, TrakkarLP) | Raid-Shoutout und Whitelist-Shoutout führten getrennt Buch; nur die Whitelist trug in `shoutedOutThisSession` ein | Raid-Shoutout trägt den Raider ein, bei Misserfolg wieder entfernt | Zwei Auslöser für dieselbe Aktion teilen sich denselben Merker |
